## 1. 产品定位

一个面向固定同事群体的轻量知识分享平台。用户在网页或 AI Agent 中提交链接，平台记录谁在什么时候分享了什么，并提供足够的信息帮助同事快速了解内容。

网页是主要的链接提交入口；Claude Code、Codex 和 Cursor 是主要的内容发现与使用入口。用户可以在 Agent 中询问“最近大家分享了什么”“某位同事这周分享了什么”，获得摘要或视频描述及原始链接。

网页首页用于提交链接，下方仅展示最新 5 条分享，并提供“查看全部”入口。独立 Library 页面展示全部历史分享，按时间从新到旧排序，首次加载 10 条，滚动接近底部时再加载下一批 10 条。关键词、分享者及日期筛选集中在 Library，切换条件后从第一批重新加载；首页不显示筛选或分页。

平台负责分享记录和内容速览。需要深入理解时，用户自行阅读、观看，或让自己的 Agent 访问来源并分析。

## 2. 目标用户与核心问题

- 用户为公司内部固定的一小群同事，第一版只有一个共享空间。
- 用户经常在手机上发现有用内容，但复制链接、切换位置、整理说明等步骤使分享不容易发生。
- 接收者希望在现有 Agent 对话中了解同事的分享，不必额外养成浏览信息流的习惯。
- 分享不要求服务于某个具体问题。觉得内容有用，就可以分享；不要求填写推荐理由。

第一版接受“复制链接后到网页粘贴”的操作成本，以减少手机 App 的开发、安装和上架负担。

## 3. 产品原则

1. 分享动作尽量短：登录后粘贴链接，点击分享即可。
2. 保存分享记录与处理内容相互独立。摘要失败不等于分享失败。
3. 摘要、作者描述和原文必须明确区分，不能暗示 Agent 已读取平台未提供的完整内容。
4. 内容获取和深入分析分工清楚：平台为文章和视频生成摘要，视频结合语音和采样画面，不提供深度问答服务。
5. 同一内容尽量复用处理结果，同时保留每个人的分享记录。
6. 不承担原文归档、失效恢复或登录权限代理的责任。

### 4.1 明确不做

- 手机 App、手机系统分享扩展、浏览器扩展。
- 多团队创建、团队切换和公开社区。
- 点赞、评论、排行榜、个性化推荐和复杂分类。
- 阅读进度、未读状态和跨 Agent 阅读进度同步。
- 平台内聊天、跨文章深度分析或视频问答。
- 完整字幕转录、视频画面分析和媒体文件长期保存。
- 原文长期归档、媒体文件托管、失效链接恢复。
- 访问付费或登录内容所需的账号代理、登录绕过。

## 5. 核心使用流程

### 5.1 网页分享

1. 用户使用公司 Google 账号登录，通过成员资格检查。
2. 用户粘贴文章或 YouTube 链接并提交。
3. 平台保存原始链接、分享者和分享时间，立即显示分享成功。
4. 后台识别内容类型、获取基本信息并执行相应处理。
5. 用户可以离开页面；后台处理不要求用户等待。

标题、分类和推荐理由不作为提交的必填项。第一版不需要让用户选择团队。

### 5.2 在 Agent 中了解分享

示例请求：

- “What has everyone shared recently?”
- “What did Alice share this week?”
- “Find recent shares about AI coding.”
- “Share this link with the team: …”

Agent 调用平台查询工具，获得分享者、时间、标题、摘要或描述、来源类型和原始链接，再使用自身模型组织回答。

查询工具支持明确的起止时间、分享者筛选和分页。没有指定时间的“最近”使用一个明确的默认窗口；默认值见第 12 节，不承诺跨对话记忆阅读进度。

### 5.3 深入理解内容

1. 用户对某条内容继续追问。
2. Plugin 返回已保存的摘要或描述、原始链接和内容范围说明。
3. Agent 可以基于现有摘要做有限解释；涉及摘要之外的细节时，应使用自己的工具访问来源，或说明信息不足。
4. 平台不为这次追问重新抓取全文、调用视频分析或提供专门的深度分析接口。

能否访问原文或理解视频取决于用户 Agent 的工具和来源网站的可用性，不属于平台保证的能力。

## 6. 内容处理规则

### 6.1 文章

- 尝试提取可访问的文章正文，排除导航、广告等无关内容。
- 从获取到的正文生成英文摘要：一句话概述、3–5 个要点、原文链接。
- 正文仅用于处理过程，不长期归档；摘要生成完成后清理临时正文。
- 若读取不完整或正文不足以形成可靠摘要，不根据标题或网页描述编造全文摘要。
- 登录限制、付费墙、抓取失败或模型失败时，保留分享记录和已获取的基本信息，显示无法生成摘要。
- 摘要失败支持手动重试；成功结果供后续分享和查询复用。
- 记录摘要生成时间和模型标识，便于排查质量与成本问题。

### 6.2 YouTube 视频

文章摘要和视频摘要均使用 Gemini，每个任务执行一次模型调用。

- 提取视频标识，保存原始链接及可识别的规范链接。
- 获取可用的标题、频道、封面 URL、作者填写的 Description；时长等字段可在易于取得时保存。
- Description 明确标注为 `Video description`。它可能包含推广信息或外部链接，不等同于视频全文摘要。
- 不要求每个视频都有描述，没有描述不视为处理失败。
- 描述按来源语言保存，不为了统一英文界面调用模型翻译或重写。
- 网页使用 YouTube 嵌入播放器；无法嵌入时保留预览与 `Watch on YouTube` 链接。
- 后台把规范 YouTube URL 直接交给 Gemini，使用非流式请求一次生成英文概述及 3–5 个要点；长视频降低画面采样。
- 平台不下载、上传或保存音频/视频，不保存完整转录；只保存摘要和必要用量记录。
- 摘要标为 `AI video summary`，新摘要注明基于语音和采样画面，旧音频摘要保留历史说明；不生成或校验时间戳。
- Gemini 无法访问视频或请求失败时保留链接、显示明确失败并支持手动重试。旧视频仅有描述时也可手动生成摘要。
- 作者描述中的时间点可以原样保留，但不承诺自动生成或验证关键时间点。

### 6.3 重复分享与撤回

- 分离“内容”与“分享记录”：内容可复用，多位用户的分享分别记录。
- 识别同一 YouTube 视频时以视频标识为依据；文章 URL 规范化采用保守规则，保留原始链接，不随意删除可能影响内容的参数。
- 已有文章摘要直接复用，不因另一位同事分享而再次调用模型。
- 同一内容仍在处理中时，复用处理任务，避免并发重复生成。
- 用户可以撤回自己的分享记录；不删除其他人的分享记录。
- 提交按钮重复点击或网络重试应保证幂等；用户主动再次分享是否合并，使用第 12 节的建议默认规则。
- 原文后续失效不自动撤回分享，不恢复来源内容，不承诺持续检查链接可用性。

### 6.4 处理状态

| 场景 | 英文展示 | 含义 |
| --- | --- | --- |
| 分享已保存 | `Shared` | 链接和分享记录已入库，与摘要状态独立 |
| 文章排队或处理中 | `Generating summary` | `queued` 等待 Worker 领取；`processing` 已被领取，尚不代表模型请求已经发出 |
| 文章摘要完成 | `Ready` | 已有可读取的 AI 摘要 |
| 文章处理失败 | `Unable to generate summary` | 保留链接，可手动重试 |
| 视频排队 | `Video summary queued` | `queued` 等待领取 |
| 视频处理中 | `Generating video summary` | `processing` 正在获取元数据或生成摘要 |
| 视频摘要完成 | `Ready` | 新流程已保存视频摘要；历史只含描述的 ready 记录仍兼容，可手动生成摘要 |
| 视频处理失败 | `Unable to generate summary` | 保留原始链接，支持手动重试；无法访问视频另有具体提示 |

无法嵌入播放与无法读取基本信息是不同情况，不应把禁止嵌入标记为摘要失败。

## 7. 身份、权限与成员范围

- 使用 Google 登录，仅请求身份识别所需的信息，不需要 Gmail 邮件读取权限。
- 服务端完成 Google 身份验证，再校验 Google 返回的已验证邮箱精确属于 `@authright.com`；不能相信客户端自填邮箱。不额外限制 Google `hd` 声明。
- 公司邮箱域名是唯一准入限制。首次登录自动建立普通成员，无需手动添加、邀请或审批；不提供成员禁用功能。
- 使用稳定的用户标识关联身份，姓名与邮箱作为可更新资料。
- 显示名优先使用 Google 姓名；缺失或仅有空白时，使用邮箱 `@authright.com` 前的内容，例如 `tao.xu`。
- 网页与 Agent 共用平台用户身份；分享者由服务端认证结果决定，不由 Agent 自填。
- 成员可以查看共享空间内的有效分享、提交链接、撤回自己的分享。
- 管理员可以查看已登录成员并调整角色；角色不影响公司用户的基本访问资格。当前不要求额外的用量或审计管理页面。
- 网页与 Agent 使用同一公司邮箱资格检查。用户仍可撤销自己的单个 Agent 连接；历史分享记录保留。
- Agent 使用平台授权凭据；文章摘要服务的模型 Key 留在服务端，不发给客户端或同事。

## 8. Agent 接入契约

提供一个远程 MCP 服务，分别完成 Claude Code、Codex 和 Cursor 的连接与身份验证。具体配置形式可以不同，业务能力与权限规则应一致。

建议提供的工具能力如下，名称为实现建议，不构成最终接口名称：

| 工具能力 | 输入 | 返回内容 |
| --- | --- | --- |
| 提交分享 | URL、可选幂等标识 | 分享标识、保存结果、处理状态 |
| 查询分享 | 分享者、起止时间、关键词、分页参数 | 分享列表、分页信息、实际查询范围 |
| 获取分享详情 | 分享标识 | 元数据、摘要或描述、原始链接、处理状态 |
| 查询成员 | 姓名或邮箱关键词 | 可筛选的团队成员，帮助消除同名歧义 |
| 撤回自己的分享 | 分享标识 | 操作结果 |

不提供全文读取、视频转录、视频分析或文章深度问答工具。

每条返回内容应明确包含：

- 内容类型：`article` 或 `youtube`。
- 内容来源：`ai_article_summary`、`ai_video_summary`、`youtube_description` 或 `none`。
- 完整内容可用性：`full_content_available: false`。
- 分享者、分享时间、标题、来源链接及处理状态。
- 文章的概述与要点，或视频原始描述。两者不可混用标签。
- 必要时包含“仅摘要/描述，进一步细节需访问来源”的说明。

列表默认返回精简信息；详情可返回完整的已保存摘要或描述。Plugin 不在服务端为每次查询额外调用模型，列表汇总由调用方 Agent 完成。

文章或视频描述中的文字作为来源数据处理，不作为改变 Agent 行为或授权范围的指令。

## 9. 最小数据与存储方案

| 数据实体 | 主要内容 |
| --- | --- |
| 用户/成员 | 稳定身份标识、姓名、邮箱、成员状态、管理员标识 |
| 内容 | 类型、原始/规范链接、视频标识、标题、封面 URL、摘要或描述、来源标识、处理状态 |
| 分享记录 | 内容标识、分享者、分享时间、撤回状态 |
| 处理任务 | 内容标识、任务状态、尝试次数、失败原因、处理时间 |
| 用量记录 | 服务、任务、Token 等可获得用量、估算费用及其估算依据 |
| 设置 | 限额开关、限额值、查询默认值 |
| Agent 授权 | 用户关联、凭据状态及撤销信息；具体认证机制待技术设计 |

第一版使用数据库保存上述记录。无媒体托管及长期正文存储需求，不引入 S3 bucket 作为必需依赖。临时抓取数据应有清理机制，避免经日志或任务载荷变成长久归档。

## 10. 用量与费用控制

- 当前 Gemini API 项目使用 Free tier，文章摘要的 Gemini 文本输入/输出免费；视频一次 Gemini 调用同样计量，并保留缓存输入用量，按实际配置的 Free/Paid 档位估算费用。托管、数据库和其他服务费用另算。
- 记录模型请求数、输入 Token、处理次数和失败重试次数；Free tier 已知成功调用金额为零，未知用量不记成零。切换 Paid tier 后才按对应价格快照估算费用。
- Gemini 项目的 RPM、输入 TPM 和 RPD 限制仍然生效；初期触限时保留分享、提示摘要失败，并允许额度恢复后手动重试。试用中若频繁触限，再增加自动等待和恢复。
- 已有可配置的产品月额度默认关闭；当前不提供管理员配置页面，使用一段时间后再决定是否需要。
- 即使不启用额度限制，也要控制并发、设置任务超时和有上限的失败重试，防止重复调用。
- 启用额度后，超额不阻止保存分享链接；文章摘要任务暂停或延后，并说明原因。
- 外部 API 自身的配额继续有效；不把“产品不限额”呈现为“外部服务无限可用”。
- 用户让自己的 Agent 深入分析时，相关调用由用户自己的服务承担；平台不在查询后隐式触发额外分析。

## 11. 验收标准

1. 已验证的 `@authright.com` Google 用户首次登录自动加入；其他域名或未验证邮箱不能通过网页或 Agent 读取团队分享，不设置额外允许名单。
2. 手机浏览器中，已登录用户只需粘贴链接并提交，无需标题、分类或推荐理由。
3. 模型服务失败时，分享记录仍成功保存，且用户可以返回原始链接。
4. 可获取正文的文章生成英文的一句话概述和 3–5 个要点；无法获取可靠正文时不伪造摘要。
5. YouTube 分享展示视频摘要、可用的标题、封面、原始 Description 和链接，摘要与作者描述明确区分；没有描述也能正常分享。
6. YouTube URL 经过 Gemini 非流式一次调用，生成英文概述及 3–5 个要点；结合语音和采样画面，不要求时间戳对齐，不能嵌入时可以跳转 YouTube。
7. 不同同事分享同一内容时，都能按人查到自己的分享；文章只需复用同一份成功摘要。
8. 三个 Agent 分别完成连接验证，并能提交链接、按人和时间查询、获取摘要或描述及来源链接。
9. Agent 返回内容明确标注摘要/描述来源及“没有全文或完整转录”，不声称已提供完整内容。
10. 同事撤回自己的分享后，该记录不再出现在普通查询中，其他同事的分享不受影响。
11. 后台记录可核对的模型用量；产品侧月额度默认关闭。外部 API 触限时保留分享并提示失败，额度恢复后可手动重试；无需额外管理页面。
12. 数据库不长期保存文章正文、视频或音频；任务结束后的临时内容按清理策略处理。
13. 产品界面与生成的摘要默认英文，视频来源描述保留原语言。

## 12. 实现建议默认值与待选事项

以下是为后续实现提供的建议，不冒充已经逐项确认的产品决定。

### 12.1 建议默认行为

- Agent 工具的“最近”默认最近 7 天，首次返回不超过 20 条；工具返回实际时间窗口并支持分页。网页首页取最新 5 条，Library 默认全部历史，每批 10 条，独立于工具默认窗口。
- 时间戳统一保存，用户时区用于解释“今天”“这周”等表达；接口尽量使用明确起止时间。
- 关键词搜索先覆盖标题、摘要和视频描述，不做全文检索或向量数据库。
- 同一用户对同一内容主动再次分享，可形成新记录；按钮重复点击和网络重试不形成新记录。
- 初次访问后的登录保持、凭据过期与撤销遵循选定认证方案，兼顾手机提交便利性。

### 12.2 实现前需要确定的配置

- 产品正式名称、公司 Workspace 域名、首批成员及管理员。
- 网页和后端技术栈、数据库、部署位置及域名。
- Google 登录应用配置及公司管理员可能要求的授权设置。
- 文章提取方案、摘要模型供应商及其服务端凭据。
- YouTube 基本信息获取方式及所需凭据/配额。
- MCP 的个人授权机制，以及三个客户端的具体安装配置。

这些配置不改变本文件确定的产品边界。视频 URL 非流式摘要已按 2026-09-29 用户修订接入；文章和视频处理均选择 Gemini。

## 13. 早期验证方式

先用少量真实链接验证完整流程，不预设未经验证的成功率或成本目标。

- 同事能否顺利完成 Google 登录、手机粘贴分享和 Agent 接入。
- 常用文章来源的正文提取成功率、摘要准确性及每篇处理成本。
- YouTube 元数据和 URL 视频摘要各阶段成功率，以及嵌入失败时的跳转体验。
- 三个 Agent 按人、时间、关键词查询的结果是否准确。
- 同事是否愿意持续分享，以及是否实际通过 Agent 查询内容。
